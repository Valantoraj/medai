  LLM SHORTLIST: 2–4 GB MODELS THAT RUN ON CPU
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  All sizes are Q4_K_M quantization (best quality/size trade-off).
  All run on CPU via Ollama — no GPU required.
  ARM64 support confirmed for Oracle Cloud Free Tier.

  Model                Disk / RAM    Params   Why it fits MedAI
  ─────────────────────────────────────────────────────────────────────────
  llama3.2:3b          2.0 GB        3B       Meta's latest small model.
                                              Strong instruction following,
                                              good medical knowledge.
                                              Best all-rounder at this size.

  phi4-mini:latest     2.5 GB        3.8B     Microsoft Phi-4 Mini.
                                              Exceptional reasoning for size.
                                              Fast (~28 tok/sec on CPU).
                                              Best if you want speed.

  qwen2.5:3b           1.9 GB        3B       Alibaba Qwen 2.5.
                                              Strong at structured output
                                              (good for guidance JSON).

  gemma3:4b            3.3 GB        4B       Google Gemma 3.
                                              Best multilingual support.
                                              Good medical/scientific text.

  mistral:7b-q4        4.1 GB        7B       If you can spare 5 GB RAM.
                                              Noticeably better guidance
                                              quality than 3B models.
                                              Still CPU-viable.
  ─────────────────────────────────────────────────────────────────────────

  RECOMMENDATION for MedAI:
    Primary:  llama3.2:3b  — best balance of quality, size, speed on ARM CPU
    Fallback: phi4-mini    — faster responses if latency matters more

  To pull on your machine / the deployment server:
    ollama pull llama3.2:3b

    This is acceptable for a personal/demo deployment, not for production traffic.

  DEPLOYMENT PLAN: STEP BY STEP (Oracle Cloud + Docker Compose)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  PHASE 1 — Change LLM to llama3.2:3b (30 minutes, do this first)
  ────────────────────────────────────────────────────────────────
  In application.yml, change every model reference to llama3.2:3b:

    app:
      ollama:
        models:
          mental-health:   llama3.2:3b
          common-disease:  llama3.2:3b
          complex-disease: llama3.2:3b
          medicine:        llama3.2:3b
          fallback:        llama3.2:3b
          guidance:        llama3.2:3b
          embedding:       nomic-embed-text:latest   # keep this, 274 MB

  Pull the model locally to test:
    ollama pull llama3.2:3b

  Test the app locally with the new model, confirm guidance text works.


  PHASE 2 — Prepare ML service requirements.txt (10 minutes)
  ────────────────────────────────────────────────────────────
    cd /home/psg/Desktop/medai/ml_service
    venv/bin/pip freeze > requirements.txt

  Manually trim requirements.txt to remove dev/test packages.
  Keep: flask, flask-cors, ultralytics, torch (CPU), torchvision,
        Pillow, numpy, joblib, scikit-learn, lightgbm, xgboost,
        catboost, pandas


  PHASE 3 — Create Dockerfiles (1 hour)
  ────────────────────────────────────────────────────────────

  File: Dockerfile.spring
  ─────────────────────────
    FROM eclipse-temurin:17-jre-alpine
    WORKDIR /app
    COPY target/medai-1.0.0.jar app.jar
    EXPOSE 8080
    ENTRYPOINT ["java", "-Xmx512m", "-jar", "app.jar"]


  File: ml_service/Dockerfile.ml
  ─────────────────────────
    FROM python:3.13-slim
    WORKDIR /app

    # System deps for OpenCV / PIL
    RUN apt-get update && apt-get install -y --no-install-recommends \
        libgl1 libglib2.0-0 libsm6 libxext6 && rm -rf /var/lib/apt/lists/*

    COPY requirements.txt .
    # CPU-only torch to keep image size small (~800 MB instead of 2.5 GB)
    RUN pip install --no-cache-dir torch torchvision --index-url https://download.pytorch.org/whl/cpu
    RUN pip install --no-cache-dir -r requirements.txt

    COPY . .
    EXPOSE 5001
    CMD ["python", "app.py"]


  IMPORTANT — exclude model files from the Docker image.
  They are too large to bake in. Use a volume mount instead:

  File: .dockerignore (in ml_service/)
  ─────────────────────────
    venv/
    blood_cancer_dataset/
    runs/
    *.pt
    run_ml_models/
    __pycache__/
    .history/


  File: docker-compose.yml (project root)
  ─────────────────────────────────────────
    version: "3.9"

    services:
      postgres:
        image: postgres:16-alpine
        restart: unless-stopped
        environment:
          POSTGRES_DB: medai
          POSTGRES_USER: medai
          POSTGRES_PASSWORD: "${DB_PASSWORD}"
        volumes:
          - pgdata:/var/lib/postgresql/data
        healthcheck:
          test: ["CMD-SHELL", "pg_isready -U medai"]
          interval: 10s
          timeout: 5s
          retries: 5

      ollama:
        image: ollama/ollama:latest
        restart: unless-stopped
        volumes:
          - ollama_data:/root/.ollama
        ports:
          - "127.0.0.1:11434:11434"   # not exposed externally

      ml-service:
        build:
          context: ./ml_service
          dockerfile: Dockerfile.ml
        restart: unless-stopped
        volumes:
          # Mount model files from the host — not baked into image
          - ./ml_service/blood_cancer_model.pt:/app/blood_cancer_model.pt:ro
          - ./ml_service/lung_cancer_model.pt:/app/lung_cancer_model.pt:ro
          - ./ml_service/kidney_cancer_cyst_stone_model.pt:/app/kidney_cancer_cyst_stone_model.pt:ro
          - ./ml_service/skin_cancer_model.pt:/app/skin_cancer_model.pt:ro
          - ./ml_service/runs:/app/runs:ro
          - ./ml_service/run_ml_models:/app/run_ml_models:ro
        ports:
          - "127.0.0.1:5001:5001"     # not exposed externally
        environment:
          - PYTHONUNBUFFERED=1

      spring-boot:
        build:
          context: .
          dockerfile: Dockerfile.spring
        restart: unless-stopped
        ports:
          - "8080:8080"
        environment:
          - SPRING_DATASOURCE_URL=jdbc:postgresql://postgres:5432/medai
          - SPRING_DATASOURCE_USERNAME=medai
          - SPRING_DATASOURCE_PASSWORD=${DB_PASSWORD}
          - SPRING_AI_OLLAMA_BASE_URL=http://ollama:11434
          - APP_ML_SERVICE_BASE_URL=http://ml-service:5001
          - APP_JWT_SECRET=${JWT_SECRET}
        depends_on:
          postgres:
            condition: service_healthy

    volumes:
      pgdata:
      ollama_data:


  File: .env (project root — NEVER commit to git)
  ─────────────────────────
    DB_PASSWORD=change_this_to_random_string
    JWT_SECRET=change_this_to_64_char_hex_string


  PHASE 4 — Provision Oracle Cloud Free Tier (1–2 hours)
  ────────────────────────────────────────────────────────
  1. Sign up at cloud.oracle.com/free (use a real credit card, won't charge)
  2. Create instance:
       Shape:    VM.Standard.A1.Flex
       OCPUs:    4
       Memory:   24 GB
       OS:       Ubuntu 22.04 (ARM64)
       Storage:  200 GB boot volume
  3. Open ports in Oracle's Security List:
       Ingress TCP 22   (SSH)
       Ingress TCP 80   (HTTP)
       Ingress TCP 443  (HTTPS)
       Ingress TCP 8080 (or proxy via nginx)
  4. Also open in the Ubuntu firewall on the instance:
       sudo ufw allow 22 && sudo ufw allow 80 && sudo ufw allow 443
       sudo ufw allow 8080 && sudo ufw enable


  PHASE 5 — Set up the server (1 hour)
  ────────────────────────────────────────────────────────
  SSH in, then:

    # Install Docker
    curl -fsSL https://get.docker.com | sudo sh
    sudo usermod -aG docker $USER && newgrp docker

    # Install Ollama
    curl -fsSL https://ollama.com/install.sh | sh

    # Pull the small LLM and embedding model
    ollama pull llama3.2:3b
    ollama pull nomic-embed-text:latest


  PHASE 6 — Transfer project files (30 minutes)
  ────────────────────────────────────────────────────────
  From your local machine:

    # Build the JAR first
    cd /home/psg/Desktop/medai
    mvn clean package -DskipTests

    # Copy files to server (replace SERVER_IP)
    rsync -avz --exclude='ml_service/venv' \
               --exclude='ml_service/blood_cancer_dataset' \
               --exclude='.git' \
               --exclude='target/classes' \
               --exclude='target/generated-sources' \
               /home/psg/Desktop/medai/ \
               ubuntu@SERVER_IP:/home/ubuntu/medai/


  PHASE 7 — Start the application
  ────────────────────────────────────────────────────────
  On the server:

    cd /home/ubuntu/medai
    cp .env.example .env          # fill in DB_PASSWORD and JWT_SECRET
    docker compose up -d --build

    # Watch logs
    docker compose logs -f


  PHASE 8 — Add HTTPS with Caddy (15 minutes, requires a domain)
  ────────────────────────────────────────────────────────────────
  Caddy auto-provisions Let's Encrypt certificates.

    sudo apt install -y debian-keyring debian-archive-keyring apt-transport-https
    curl -1sLf 'https://dl.cloudflare.com/release/signing.gpg' | sudo gpg --dearmor -o /usr/share/keyrings/cloudflare-main.gpg
    sudo apt install caddy

    # /etc/caddy/Caddyfile
    yourdomain.com {
        reverse_proxy localhost:8080
    }

    sudo systemctl restart caddy

  Point your domain's A record to SERVER_IP. HTTPS works automatically.

  If you don't have a domain, use Cloudflare Tunnel (free) instead:
    cloudflared tunnel --url http://localhost:8080

  1. application.yml — make DB password and JWT secret read from env vars:
       spring.datasource.password: ${DB_PASSWORD:medai_password}
       app.jwt.secret: ${JWT_SECRET:default_secret}
       spring.ai.ollama.base-url: ${OLLAMA_BASE_URL:http://localhost:11434}
       app.ml-service.base-url: ${ML_SERVICE_URL:http://localhost:5001}

  2. application.yml — change all models to llama3.2:3b (see Phase 1)

  3. CORS — change allowed origins from localhost:8080 to your domain:
       In app.py:  CORS(app, origins=["https://yourdomain.com"])
       In Spring Security config: update CORS allowed origins

  4. Static cache — already set to no-cache in development.
     For production set it back to a reasonable value:
       spring.web.resources.cache.period: 86400  # 24 hours

  5. generate a strong JWT secret (run this locally):
       openssl rand -hex 32

  6. generate a strong DB password:
       openssl rand -base64 24
