================================================================================
  SECTION 1 — PROJECT OVERVIEW
================================================================================

MedAI is a unified healthcare web application built on Spring Boot (Java) with
a modern HTML/CSS/JS frontend. It replaces the reference Django-based HealthHub
project with a Spring Boot architecture while using locally-hosted Ollama LLM
models for all AI features (no training required — all pre-trained models).

Core Features:
  1. Mental Health Chatbot (conversational, memory-aware, cross-session)
  2. Common Disease Diagnoser Chatbot (conversational, confidence-scored)
  3. Complex Disease Diagnoser Chatbot (conversational, confidence-scored)
  4. Medicine Information Chatbot (conversational + single-ask mode)
  5. Nearby Hospital Finder (live map with routing)
  6. Personalisation Engine (toggle-able, records all interactions)
  7. User Authentication & Profile Management
  8. Light/Dark Theme Toggle
  9. Report-Based Disease Risk Prediction (6 models via ML forms):
       - Heart Disease, Stroke, Diabetes, Lung Cancer (risk factors),
         Kidney Stone, Liver Disease
       - User fills structured form → ML model outputs risk % →
         Ollama LLM generates personalised medical guidance
  10. Image-Based Cancer Diagnosis (5 models via image upload):
       - Lung Cancer (CT scan), Skin Cancer (dermoscopy),
         Blood Cancer/Leukemia (blood smear), Kidney (CT scan),
         Brain Tumor (MRI)
       - User uploads medical scan → CNN/ViT model classifies condition →
         Ollama LLM generates personalised guidance + triggers hospital
         finder if severity is HIGH/CRITICAL

────────────────────────────────────────────────────────────────────────────────
  5.1  CHATBOT ARCHITECTURE (Shared across all chatbot features)
────────────────────────────────────────────────────────────────────────────────

All chatbots share a common architecture:

  User Input → ChatController → ChatService → [Specific Service] → OllamaService
                                                     ↓
                                              ConfidenceEngine
                                                     ↓
                                              Database (persist)
                                                     ↓
                                              Response → User

CONVERSATION MEMORY (cross-session):
  - Every message (user + assistant) is stored in `chat_messages` table
  - Linked to `chat_sessions` table, which tracks session metadata
  - When a new session starts, the system loads the LAST N messages from
    ALL previous sessions for that user + chatbot type
  - These are injected into the Ollama prompt as conversation history
  - This makes the chatbot memory-aware across sessions
  - Spring AI's ChatMemory with JdbcChatMemory advisor handles this

DOCTOR-LIKE BEHAVIOR:
  - System prompt instructs the model to behave as a doctor
  - Must ASK questions one at a time, not dump information
  - Must wait for user response before asking the next question
  - Must not diagnose prematurely — gather enough symptoms first
  - System prompt template (in PromptTemplates.java):

    """
    You are Dr. MedAI, a compassionate and thorough medical professional.
    RULES:
    1. Ask ONE question at a time about the patient's symptoms
    2. Wait for the patient's response before asking the next question
    3. Never give a diagnosis until you have asked at least 5 relevant questions
    4. After each response, internally update your confidence about possible
       conditions (you will receive a function call for this)
    5. When confidence exceeds 80% for any condition, provide your assessment
    6. Always recommend seeing a real doctor for serious conditions
    7. Be empathetic, clear, and use simple language
    """

CONFIDENCE SCORE ENGINE (ConfidenceEngine.java):
  - Maintains a map of {disease/condition → confidence_percentage}
  - Stored in `confidence_scores` table per user per session
  - After each user response, the LLM is asked (via tool/function calling):
      "Based on the conversation so far, update confidence scores for
       suspected conditions. Return JSON: [{condition, confidence, reasoning}]"
  - The ConfidenceEngine parses this and updates the DB
  - Threshold: when any condition reaches ≥ 80% confidence:
      → The chatbot delivers the prediction
      → Provides healthcare guidance
      → Suggests nearby hospitals if condition is serious (triggers hospital API)
  - Confidence scores are shown in a sidebar widget in the chat UI

STREAMING RESPONSES:
  - Use Server-Sent Events (SSE) via Spring's SseEmitter
  - Endpoint: GET /api/chat/stream?sessionId=...
  - Chat responses stream token-by-token for a natural feel
  - Frontend uses EventSource API to receive and render tokens

  5.2  MENTAL HEALTH CHATBOT
────────────────────────────────────────────────────────────────────────────────

Model: medllama2 (ollama pull medllama2)
Endpoint: POST /api/chat/mental-health

Behavior:
  - Acts as a compassionate mental health counselor
  - Asks about mood, sleep, appetite, social behavior, stress, etc.
  - Tracks confidence scores for: depression, anxiety, PTSD, bipolar,
    OCD, ADHD, insomnia, burnout, grief, etc.
  - When threshold met → provides coping strategies + professional referral
  - SAFETY: system prompt includes crisis detection keywords
    → If suicidal ideation detected, immediately provide crisis hotline numbers
    → Never attempt to treat crisis situations via chatbot

Memory: Full cross-session memory. Chatbot remembers past conversations
  and can say things like "Last time we spoke, you mentioned feeling
  overwhelmed at work. How has that been?"


────────────────────────────────────────────────────────────────────────────────
  5.3  COMMON DISEASE DIAGNOSER
────────────────────────────────────────────────────────────────────────────────

Model: medllama2
Endpoint: POST /api/chat/common-disease

Behavior:
  - Handles common ailments: cold, flu, allergies, headache, fever, stomach
    issues, skin rashes, minor infections, etc.
  - Asks symptom questions one by one
  - Tracks confidence for multiple possible conditions simultaneously
  - When threshold met → provides:
      → Disease name + confidence %
      → Suggested OTC medications
      → Home remedies
      → When to see a doctor
  - If symptoms suggest something serious → escalates to complex diagnoser


────────────────────────────────────────────────────────────────────────────────
  5.4  COMPLEX DISEASE DIAGNOSER
────────────────────────────────────────────────────────────────────────────────

Model: meditron (ollama pull meditron)
Endpoint: POST /api/chat/complex-disease

Behavior:
  - Handles serious conditions: heart disease, diabetes indicators, stroke
    symptoms, cancer warning signs, kidney/liver issues, etc.
  - More thorough questioning (asks about family history, lifestyle, etc.)
  - Confidence threshold set higher: 85% before prediction
  - When threshold met → provides:
      → Condition name + confidence %
      → Urgency level (low / medium / high / emergency)
      → Recommended specialist type
      → If HIGH/EMERGENCY → auto-triggers nearby hospital finder with
        the user's location, showing relevant hospital specialties
      → Recommended diagnostic tests


────────────────────────────────────────────────────────────────────────────────
  5.5  MEDICINE INFORMATION CHATBOT
────────────────────────────────────────────────────────────────────────────────

Model: qwen3.5:latest (already installed)
Endpoint: POST /api/medicine/chat (conversational mode)
          POST /api/medicine/query (single-ask mode)

TWO MODES:
  A) Conversational Mode:
     - User can have a back-and-forth about medications
     - "What are the side effects of ibuprofen?"
     - "Can I take it with paracetamol?"
     - "What about if I'm pregnant?"
     - Memory-aware within the session

  B) Single-Ask Mode:
     - User types a question, gets a single comprehensive response
     - No follow-up context maintained
     - Toggle between modes in the UI

SAFETY GUARDRAILS (in system prompt):
  - Never recommend specific dosages without knowing patient details
  - Always say "consult your doctor/pharmacist for exact dosage"
  - Never provide information about drug abuse or harmful combinations
  - Flag dangerous drug interactions prominently
  - Do not provide information about controlled substances procurement


────────────────────────────────────────────────────────────────────────────────
  5.6  NEARBY HOSPITAL FINDER
────────────────────────────────────────────────────────────────────────────────

NO external paid API needed. All free/open-source.

Technologies:
  - Leaflet.js — map rendering (CDN, no install needed)
  - OpenStreetMap — free map tiles
  - Overpass API — query hospitals from OSM data (free, no API key)
  - Leaflet Routing Machine + OSRM — free routing/navigation
  - HTML5 Geolocation API — get user's current location

Frontend Page: hospitals.html

Flow:
  1. Page loads → request user's GPS location via Geolocation API
  2. Send coordinates to backend: GET /api/hospitals/nearby?lat=X&lon=Y&radius=5000
  3. Backend calls Overpass API:
     Query: [out:json];(node(around:5000,LAT,LON)["amenity"="hospital"];
            way(around:5000,LAT,LON)["amenity"="hospital"];);out center;
  4. Backend parses response, extracts: name, lat, lon, phone (if available),
     address, website, emergency status
  5. Returns JSON list to frontend
  6. Frontend renders:
     - User location as a blue pin
     - Each hospital as a red pin with popup showing name/phone/address
     - Click hospital pin → show route from user to hospital
     - Route updates dynamically (recalculates if user moves)
  7. Hospital list also shown as a sidebar panel with:
     - Distance from user
     - Contact number (if available from OSM data)
     - Click to navigate button

INTEGRATION WITH CHATBOTS:
  - When disease diagnoser detects a serious condition (HIGH/EMERGENCY urgency):
    → ChatResponse includes a field: triggerHospitalFinder = true
    → Frontend auto-opens the hospital finder panel
    → Hospitals are filtered by relevant specialty if available
    → Urgency banner shown: "Based on your symptoms, we recommend visiting
      a hospital. Here are the nearest ones:"


────────────────────────────────────────────────────────────────────────────────
  5.7  PERSONALISATION ENGINE
────────────────────────────────────────────────────────────────────────────────

CORE CONCEPT:
  Every user interaction is logged. The system adapts over time.

Toggle: Users can switch between:
  - PERSONALISED MODE: chatbots use past interaction history to tailor responses
  - GENERAL MODE: chatbots behave as if talking to a new user

Storage:
  - `user_interactions` table: logs every interaction with metadata
    (timestamp, feature_used, input_summary, output_summary, sentiment)
  - `user_preferences` table: derived preferences
    (preferred_language_style, known_conditions, medication_history, etc.)
  - Vector embeddings (via nomic-embed-text) stored in pgvector
    for semantic retrieval of relevant past interactions

How Personalisation Works:
  1. User sends a message in any chatbot
  2. If personalisation is ON:
     a. Embed the user's message using nomic-embed-text
     b. Query pgvector for top-5 similar past interactions
     c. Inject relevant past context into the system prompt:
        "Patient history context: Previously reported chronic headaches
         (2 months ago), takes ibuprofen regularly, allergic to aspirin."
     d. LLM generates a personalised response
  3. If personalisation is OFF:
     a. Skip steps 2a-2c
     b. LLM generates a generic response

UI Toggle:
  - Persistent toggle switch in the top navbar
  - Stored in localStorage + synced to server
  - Visual indicator: "🔵 Personalised" or "⚪ General"

================================================================================
  SECTION 8 — DATABASE SCHEMA
================================================================================

TABLE: users
  id              BIGSERIAL PRIMARY KEY
  username        VARCHAR(50) UNIQUE NOT NULL
  email           VARCHAR(100) UNIQUE NOT NULL
  password_hash   VARCHAR(255) NOT NULL
  full_name       VARCHAR(100)
  date_of_birth   DATE
  phone           VARCHAR(20)
  gender          VARCHAR(10)
  personalisation BOOLEAN DEFAULT TRUE
  created_at      TIMESTAMP DEFAULT NOW()
  last_login      TIMESTAMP

TABLE: chat_sessions
  id              BIGSERIAL PRIMARY KEY
  user_id         BIGINT REFERENCES users(id)
  bot_type        VARCHAR(30) NOT NULL
                  -- values: MENTAL_HEALTH, COMMON_DISEASE, COMPLEX_DISEASE, MEDICINE
  started_at      TIMESTAMP DEFAULT NOW()
  ended_at        TIMESTAMP
  is_active       BOOLEAN DEFAULT TRUE

TABLE: chat_messages
  id              BIGSERIAL PRIMARY KEY
  session_id      BIGINT REFERENCES chat_sessions(id)
  role            VARCHAR(10) NOT NULL  -- USER, ASSISTANT, SYSTEM
  content         TEXT NOT NULL
  timestamp       TIMESTAMP DEFAULT NOW()

TABLE: confidence_scores
  id              BIGSERIAL PRIMARY KEY

================================================================================
  SECTION 15 — OLLAMA POST-PREDICTION MEDICAL GUIDANCE LAYER
================================================================================

After EVERY ML model prediction (both tabular and image-based), the result is
passed to a local Ollama model to generate personalised medical guidance.

This is the CRITICAL bridge between raw ML output and user-friendly advice.

────────────────────────────────────────────────────────────────────────────────
  15.1  HOW THE GUIDANCE LAYER WORKS
────────────────────────────────────────────────────────────────────────────────

FULL DATA FLOW:
  1. User fills form / uploads image on frontend
  2. Spring Boot sends to Python ML Service → gets raw prediction JSON
  3. Spring Boot's MedicalGuidanceService receives:
       { disease, risk_probability, risk_level, predicted_class }
  4. MedicalGuidanceService builds a structured prompt for Ollama
  5. Ollama (qwen3.5:latest) generates medical guidance
  6. Spring Boot combines ML output + Ollama guidance into a final response
  7. Frontend renders the rich result card

────────────────────────────────────────────────────────────────────────────────
  15.2  GUIDANCE PROMPT TEMPLATES (in PromptTemplates.java)
────────────────────────────────────────────────────────────────────────────────

TABULAR PREDICTION GUIDANCE PROMPT:
  =========================================================================
  You are Dr. MedAI, a compassionate medical advisor.

  A patient has just completed a medical risk assessment with the following
  result:

    Disease Assessed: {disease_name}
    Risk Probability: {risk_percentage}%
    Risk Level: {risk_level}  (LOW / MEDIUM / HIGH / CRITICAL)

  Patient Profile (if personalisation is ON):
    {patient_history_context}

  Please provide clear, compassionate medical guidance including:
  1. What this result means in simple terms (2-3 sentences)
  2. Immediate lifestyle actions the patient can take (3-5 bullet points)
  3. Warning signs to watch out for
  4. When they should see a doctor (urgency scale: routine / soon / urgent / emergency)
  5. Specialist type to consult if needed (e.g., cardiologist, endocrinologist)

  CRITICAL RULES:
  - Never say this replaces a doctor's diagnosis
  - Be empathetic and avoid causing panic
  - Use simple, non-technical language
  - Keep the response concise (under 300 words)
  - If risk level is CRITICAL, strongly urge immediate medical attention
  =========================================================================

IMAGE PREDICTION GUIDANCE PROMPT:
  =========================================================================
  You are Dr. MedAI, a compassionate medical advisor.

  A patient uploaded a medical image for analysis. The AI model returned:

    Cancer/Condition Type: {cancer_type}
    Predicted Class: {predicted_class}
    Confidence: {confidence_pct}%
    Image Type: {image_type}  (MRI / CT Scan / Dermoscopy / Blood Smear)

  Patient Profile (if personalisation is ON):
    {patient_history_context}

  Please provide:
  1. What the prediction means in simple terms (2-3 sentences)
  2. Whether this needs immediate attention (urgency level)
  3. What specialist to see and why
  4. What additional tests are usually recommended for this finding
  5. General coping / next step advice

  CRITICAL RULES:
  - Always emphasize that a radiologist/specialist must review the actual image
  - Never confirm or deny a diagnosis — this is a screening aid only
  - If result suggests Malignant / Tumor / Glioma etc., urge urgent specialist visit
  - Be gentle, clear, and supportive
  =========================================================================

────────────────────────────────────────────────────────────────────────────────
  15.3  RISK LEVEL → GUIDANCE BEHAVIOR MAPPING
────────────────────────────────────────────────────────────────────────────────

  ┌──────────────┬────────────────────────────────────────────────────────────┐
  │ Risk Level   │ Behavior                                                   │
  ├──────────────┼────────────────────────────────────────────────────────────┤
  │ LOW (0–30%)  │ Ollama gives preventive lifestyle advice. No alarm.        │
